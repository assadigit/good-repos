# superpowers

**`obra/superpowers`** · ⭐ 256,584 · 🔧 Shell

## What is it?
Superpowers is a software development methodology designed for AI coding agents. It provides a structured workflow that starts by clarifying requirements, then produces detailed design specifications, and finally generates implementation plans that adhere to TDD, YAGNI, and DRY principles. The framework integrates with multiple agent platforms like Claude Code and Antigravity, enabling agents to follow rigorous engineering practices.

## How does it work?
The project begins when an agent is invoked to build something; instead of jumping straight into code, it first asks the user for a clear description of the goal. This conversation extracts a spec that is broken into readable chunks for review. Once the design is approved, Superpowers creates an implementation plan that emphasizes test-driven development and minimal over-engineering. The architecture relies on composable skills that can be swapped between different agent interfaces.

## Why is it important? (Core Value)
For a software engineer interested in AI agents and developer tools, Superpowers offers a self-hostable framework that enforces disciplined coding practices within the agent ecosystem. It aligns with your interest in discovering agent frameworks and MCP servers, as it provides a methodology rather than just a library of functions. Integrating Superpowers into your Obsidian vault would give you a curated approach to building agents that respect software engineering norms, making it easier to evaluate and adopt new tools.

## Key Features & Technologies
- Supports multiple agent platforms (Claude Code, Antigravity, Codex App)
- Spec-driven development workflow with design review
- Implementation plans emphasizing TDD, YAGNI, DRY
- Composable skills architecture
- Self-hostable methodology framework

## Difference from Others
Unlike generic orchestration frameworks like LangChain or AutoGen, Superpowers focuses on the software development lifecycle itself rather than just chaining API calls. It emphasizes rigorous engineering practices such as test-driven development and You Aren't Gonna Need It, which are less common in agent-specific libraries. This makes it a distinct choice for developers who want agents to follow proven methodologies instead of ad-hoc patterns.
