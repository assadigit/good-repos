# pear-desktop

> **TL;DR:** Cross-platform Electron desktop app that extends music player functionality across macOS, Linux, and Windows.

**`pear-devs/pear-desktop`** · ⭐ 32,600 · 🔧 TypeScript

## What is it?
Pear Desktop is a cross‑platform desktop application built on Electron/Node.js that serves as an extension layer for music player functionality. It runs natively on macOS, Linux, and Windows, providing a unified UI that can interact with underlying music services or playback engines.

Key capabilities include support for custom UI components, event hooks for integrating with external services, and a modular architecture that lets developers extend its behavior via plugins or Electron IPC. The project emphasizes a clean codebase with ESLint style enforcement, indicating developer‑friendly tooling.

## How does it work?
Pear Desktop runs within the Electron runtime, which bundles a Chromium instance and Node.js environment into a single executable. Its UI is rendered using standard web technologies (HTML, CSS, JavaScript), while logic resides in Node modules that expose APIs to the underlying music player service via IPC or native bindings.

The app packages its code and assets for each target platform, leveraging Electron's build system (likely electron-builder) to produce installers for macOS, Windows, and Linux.

## Why is it important? (Core Value)
Pear Desktop offers a cross‑platform, self‑hostable UI layer for music playback, aligning with your interest in self‑hosted alternatives to SaaS products. As an open‑source Electron project, it provides a reusable base for building custom desktop tools or extending existing music services without relying on proprietary clients. Its modular architecture and developer‑friendly tooling (ESLint, CI/CD) make it a solid starting point for any of your automation or agent projects that require a desktop interface.

## Difference from Others
Unlike full-featured music players that implement their own playback engines, Pear Desktop focuses on providing an extensible UI layer that can hook into any backend, making it more modular and easier to integrate with custom services or AI agents. This approach also reduces the maintenance burden, as core media handling is delegated to existing libraries rather than being reimplemented within the app.
